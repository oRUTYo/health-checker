# PRD — Product Requirements (AI Feature)

## 1. Проблема / Возможность (Problem / Opportunity)
- <b>Проблема</b>: Анализ кардиограммы требует квалифицированного специалиста и времени. В рутинных сценариях (скрининг, предварительная диагностика) врачам не хватает быстрых инструментов для первичной оценки.
- <b>Цель</b>: Создать простой AI-сервис, который: автоматически классифицирует сердечные ритмы,
помогает выявлять аномалии (аритмии),
ускоряет предварительный анализ

## 2. Целевые пользователи (Target Users)
- Врачи-кардиологи (как вспомогательный инструмент)
- Медицинские исследователи / студенты
- Разработчики health-tech решений
- Клиники для пилотного использования

## 3. Показатели ценности и успеха (Value & Success KPIs)
 - ML-метрики:

    Accuracy ≥ 85% (на тестовом наборе)<br>
    F1-score ≥ 0.80 (важно при несбалансированных классах)

 - Продуктовые метрики:

    Время анализа одной ECG: ≤ 5 секунд <br>
    Количество успешных анализов (без ошибок системы) <br>
    Простота использования (1–2 шага до результата)


## 4. Non-Goals (Out of scope)
Для MVP НЕ делаем:
- Медицинскую сертификацию (FDA/CE)
- Постановку диагноза
- Обработку данных в реальном времени с устройств
- Интеграции с hospital systems (EHR/EMR)
- Сложные explainability (SHAP, LIME и т.д.)
- Поддержку множества форматов ECG

## 5. Constraints
 - Данные:
    1) Используем только датасет с ECG Heartbeat Categorization Dataset
    2) Возможен дисбаланс классов

 - Команда (7 человек):
    1) Ограниченные ресурсы → только MVP
    2) Параллельная разработка (frontend/backend/AI)

## 6. Risks
 - ML риски:
    1) Низкая точность на реальных данных
    2) Переобучение на датасете
    3) Дисбаланс классов

 - Продуктовые:
    1) Пользователь неправильно интерпретирует результат
    2) Ожидание "медицинского диагноза"
