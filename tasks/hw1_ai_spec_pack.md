## Рекомендации для доведения до 20/20

1. **Data Spec → секция «Data tests / contracts»**: вынести проверки в отдельный раздел (формат файла, мин. длина сигнала, диапазон значений, fail-fast для невалидных входов).
2. **DoD → сократить до 10–15 пунктов**: объединить смежные критерии (например, пункты 14–15 Frontend) или вынести часть в чек-листы отдельных модулей.
3. **DoD → добавить rollback**: kill-switch на эндпоинте `/predict` (fallback на «не уверен» при ошибке модели), процедура отката артефактов в `ml/artifacts/`.
4. **DoD → назначить владельцев**: таблица «модуль → ответственный» (AI / Backend / Frontend / DevOps).
5. **DoD → перечень тестов**: behavioral (3 эталонных сигнала по классам), data validation (длина, NaN, тип), E2E (полный сценарий через UI).
6. **`/tests/`**: положить 3–5 эталонных сигналов (`normal.json`, `vebr.json`, `unknown.json`) для behavioral-тестов.
7. **`/reports/`**: добавить `metrics.md` с финальными метриками модели, confusion matrix, графиками из ноутбука.
